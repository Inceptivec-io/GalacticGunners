# GALACTIC GUNNERS
# IP FREEDOM / LICENSE PROTECTION ASSET CREATION — INTERFACE SPECIFICATION
## GG-COM-001 v1.1

**Future Pack ID:** `IP_FREEDOM_LICENSE_PROTECTION_ASSET_CREATION`

## 1. Purpose

Create replacements for every legacy non-core media/font/utility dependency that Galactic Gunners does not need to retain.

The objective is:

> **Commercial IP freedom through deliberate creation of owned assets, while preserving the game's distinctive 90s arcade-space-shooter character in a form that feels current rather than dated.**

This is a separate work pack from GG-COM-001.

GG-COM-001 identifies what must leave the commercial dependency estate.

The IP Freedom pack creates, validates and records what replaces it.

---

## 2. Creative Position

Galactic Gunners should not be visually rebuilt into a modern photorealistic space game.

Its appeal includes its arcade nature.

Target:

```text
1990s arcade / console memory
+
clean contemporary presentation
+
modern scaling / animation / UX
+
distinctive Inceptivec-owned visual identity
```

The product should evoke the feeling of 90s games without appearing technically obsolete.

---

## 3. Asset Families to Replace / Create

### Visual

- player ship/sprite family where legacy source is not owned;
- enemy sprite families;
- boss/mothership;
- projectiles;
- nuke effect;
- explosions;
- asteroid/comet/environment hazards;
- starfield/backgrounds;
- UI icons;
- mute/sound icons;
- pause/resume icons;
- info/help icons;
- pointers/cursors where game-specific;
- title/header graphic;
- menu presentation;
- victory/game-over graphics;
- any legacy third-party decorative imagery.

### Audio

- nuke/fire sound;
- any non-MIT/non-owned audio identified during final audit;
- optionally a coherent proprietary SFX family if replacing more broadly improves sonic identity.

### Typography / Brand lettering

- proprietary Galactic Gunners wordmark/display lettering;
- UI font approach that is commercially safe;
- retain arcade character;
- maintain readability across small/mobile screens.

### Supporting code

Replace small tutorial/example utility code whose independent provenance is not worth carrying, including any affected alignment/UI helpers, with simple internally authored equivalents.

### Documentation

- remove bundled course PDF;
- use external citation/reference only;
- create owned commercial screenshots after new assets are integrated.

---

## 4. Design Rules

Must feel:

- arcade;
- responsive;
- fast;
- space-combat oriented;
- recognisable at small sizes;
- polished enough for paid mobile/desktop distribution;
- visually coherent.

Must avoid:

- photorealistic ships;
- over-detailed cinematic assets;
- generic AI-generated sci-fi art;
- faux CRT degradation as the primary aesthetic;
- excessive neon/cyberpunk styling unrelated to the game;
- childish cartoon treatment;
- sterile flat corporate UI;
- copying recognisable assets from existing franchises.

---

## 5. IP Creation Evidence

Every new asset must record:

- creator;
- creation date;
- source working file;
- prompt/reference process if any generative tooling is used;
- licence/ownership status;
- derivative-source check;
- final exported asset hash;
- repository path;
- superseded legacy asset;
- approval state.

If external contractors/designers contribute, sufficient written rights must be obtained before incorporation.

---

## 6. Completion Relationship to GG-COM-001

GG-COM-001 may close as `CONDITIONAL PASS` if:

- every required replacement is identified;
- the old asset is prevented from commercial release;
- the replacement is fully commissioned into the approved IP Freedom pack.

Full commercial-release clearance requires the IP Freedom replacement set to be completed and integrated before GG-COM-005/006 store release.
