# ACCEPTANCE CRITERIA AND PRIOR DEFECTS v1.0

## Founder-rejected defects from prior build that must not recur

1. Horrendous overall presentation quality.
2. Static gameplay ships where original behaviour had activity.
3. Poor/non-owned/generic-looking typography.
4. Awkward title screen composition.
5. Weak info page layout and giant low-quality text wall.
6. HUD overlap / poor runtime composition.
7. Flat/orange shield presentation rather than proper upgraded modular shield feel.
8. Visually weak Game Over composition.
9. Visually weak Victory composition.
10. Failure to distinguish decorative art from live event-driven interface.

## Acceptance criteria

### Visual
- Founder-supplied asset pack clearly integrated;
- supplied fonts clearly integrated;
- animation restored;
- no obvious generic browser-font look;
- title/info/victory/game-over read as finished commercial scenes.

### Runtime
- buttons clickable / selectable;
- counters update live;
- sound toggle reflects state;
- title scene selection feedback works;
- Game Over and Victory actions work through event handlers;
- shield still destructs per tile;
- no loss of gameplay semantics through art swap.

### Governance
- asset archive preserved in evidence;
- all changes tracked/committed/pushed;
- worktree clean;
- POST_BOX clean;
- one active branch only;
- no invented scope.
